# AI Insight Library

**Project:** Ümit Diet Companion
**Sprint:** Sprint 5 – Intelligence
**Version:** 1.0 (Draft)
**Status:** Design Phase

---

# Purpose

The AI Insight Library defines **how the intelligence engine understands the user's health status**.

Observations are raw facts.

Insights are meaningful interpretations of those facts.

This library provides the standardized set of insights that can be generated by the Observation Engine and consumed by the Recommendation Engine.

Every insight should have a clear definition, deterministic trigger conditions and a specific health meaning.

---

# Design Philosophy

An insight is **not** a recommendation.

It is **not** a coaching message.

It is **not** a behaviour.

An insight simply answers one question:

> **"What does the current data tell us?"**

The Recommendation Engine decides what to do next.

# Insight Object

Every insight should follow the same structure.

## Required Properties

* Insight ID
* Name
* Category
* Severity
* Description
* Trigger Rules
* Confidence
* Related Metrics
* Related Insights
* Possible Recommendations
* Coach Themes
* Priority Modifier

---

# Insight Categories

The library is organised by health domains.

* Hydration
* Nutrition
* Activity
* Recovery
* Weight
* Lifestyle
* Behaviour
* Consistency
* Motivation (Future)
* Prediction (Future)

---

# Insight Severity

Every insight includes a severity level.

Levels

* Excellent
* Good
* Neutral
* Attention
* High
* Critical

Severity influences prioritisation but never directly creates recommendations.

---

# Insight Confidence

Each insight carries a confidence score.

Examples

High

Garmin + Manual Data

Medium

Garmin only

Low

Estimated values

The Recommendation Engine should reduce confidence-dependent actions when confidence is low.

# Positive Insights

Not every insight should identify a problem.

The engine should also recognise success.

Examples

* Hydration Complete
* Excellent Recovery
* Healthy Streak
* Balanced Nutrition
* Positive Weight Trend
* Goal Approaching
* Daily Goal Achieved

Positive insights improve motivation and reinforce sustainable habits.

---

# Compound Insights

Some insights emerge only when multiple observations are evaluated together.

Examples

Sleep Debt

*

High Activity

↓

Recovery Risk

---

Alcohol

*

Poor Sleep

↓

Hydration Recovery Needed

---

Protein Deficit

*

Strength Training

↓

Muscle Recovery At Risk

Compound insights provide richer reasoning than isolated observations.

---

# Insight Relationships

Insights may strengthen or weaken each other.

Example

Poor Sleep

↓

Increases priority of

Recovery Risk

---

Hydration Complete

↓

Reduces priority of

Hydration Behind Schedule

These relationships help prevent conflicting interpretations.

---

# Insight Lifecycle

Every insight progresses through a lifecycle.

Observation

↓

Insight Detected

↓

Recommendation Generated

↓

Behaviour Selected

↓

Behaviour Completed

↓

Insight Resolved

This lifecycle allows the system to measure progress and avoid repeated coaching after successful completion.

---

# Explainability

Every insight must be traceable back to the observations that generated it.

Example

Observation

Water = 1.1 L

Time = 14:30

↓

Insight

Hydration Behind Schedule

The system should always be able to explain why an insight exists.

# Future Expansion

The library is intentionally extensible.

Future insight domains may include:

* Weather Adaptation

* Mental Wellbeing
* Heart Health
* Training Readiness

New insights should integrate into the existing architecture without changing the decision pipeline.

---

# Guiding Principle

Observations describe reality.

Insights explain reality.

Recommendations improve reality.

The AI Insight Library exists to ensure that every coaching decision begins with a clear, consistent and explainable understanding of the user's current health state.
